# Level 1: Chaining and structure

**The question this level answers:** how do I get reliable, usable results instead of one long paragraph?

L0 returned a block of prose. A person can read that, but your code cannot reliably act on it. L1 fixes two problems at once: it splits one big task into **a chain of small ones**, and it makes each step return **typed data**.

## Idea 1: a chain beats one big prompt

If you ask one prompt to "explain the CVE, assess the risk, and write a remediation plan", each part gets a fraction of the model's attention. Three focused prompts do better, and each can use what the one before it found.

{{flow: Step 1 ~ summarise the CVE | Step 2 ~ assess the risk | Step 3 ~ plan the fix}}

The output of step 1 becomes part of the input to step 2, and steps 1 and 2 both feed step 3. This is called **context accumulation**.

## Idea 2: structured output

Free text is awkward for code. If the model returns "the severity seems quite high, maybe 9ish", what do you store in a database?

With **structured output** you describe the shape you want, and the model must return data in exactly that shape. Vigil describes shapes with Pydantic classes. Here is step 1's shape:

{{include levels/l1_chain.py#CVESummary}}

Notice what the types do for you:

- `Literal["Critical", "High", "Medium", "Low"]` means the model can only answer with one of those exact words. No "CRITCAL", no "high".
- `Field(ge=0.0, le=10.0)` keeps the score between 0 and 10.
- `list[str]` and `bool` give you real lists and true/false values to program against.

Steps 2 and 3 have their own shapes, `RiskAssessment` and `RemediationPlan`. The urgency in step 2 is a fixed set of choices such as "Patch immediately" or "Patch within 7 days", so downstream code can sort and filter on it.

## The helper that does the work

One small function wraps every call in the chain:

{{include levels/l1_chain.py#call_llm}}

Two details are worth understanding:

- `response_format` with a JSON schema tells the model to return JSON that matches your class. The key line is `"strict": True`.
- `model_validate(json.loads(raw))` turns that JSON back into a real Python object and checks it. If anything is off, you get an error instead of silent bad data.

The difference from L0 is simple. L0 returns a string. `call_llm` returns an object, so you write `result.severity` and `result.cvss_score` instead of parsing text.

Step 2 receives the whole of step 1's output. Read how it builds its prompt from the previous result:

The prompt is not "assess CVE-2021-44228". It contains the facts step 1 established: the product, versions, attack vector and score. The risk assessment is **informed by** the summary. Step 3 does the same with both earlier results.

## Run it

```bash
python levels/l1_chain.py CVE-2021-44228
```

You should see three stages printed in order: a CVE summary, a risk assessment, then a remediation plan. Check that the plan reflects the risk. A critical, easy-to-exploit CVE should produce urgent immediate actions.

## Try it

That difference is the value of chaining. 2) Add a new `Literal` option to `urgency` and see whether the model uses it. 3) Make a field optional by giving it a default and note when it comes back empty.

## Common mistakes

- **Making steps too big.** If a step does three jobs, split it.
- **Passing too little forward.** A later step can only use what you give it.
- **Passing too much forward.** Every extra token costs money and can distract the model. Pass what the next step needs.
- **Trusting the type, not the content.** The shape is guaranteed; the facts are still the model's, so they can be wrong.
- **Forgetting the cost.** Three calls cost roughly three times one. Chains buy quality, not savings.

## Check yourself

??? What is context accumulation?
    Each step receives the useful results of earlier steps, so later steps build on earlier findings instead of starting from nothing.

??? Why use `Literal` types for severity?
    It limits the model to a fixed set of exact values, which removes typos and variations and lets your code branch on the result safely.

??? What does structured output guarantee, and what does it not?
    It guarantees the shape: the right fields and types. It does not guarantee that the content is true.
