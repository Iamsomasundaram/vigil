Architectures

A4: Multi-agent

The question this pattern answers: when one agent has too many jobs, how do I split the work into focused specialists?

A single agent asked to be a threat analyst, a risk assessor and a remediation planner at once can blur those roles, and its context grows with every tool result. A4 gives each job to a separate agent with its own prompt, its own tools and its own conversation.

The idea in plain English

A small incident team: three specialists each investigate their own angle at the same time, and a lead combines what they found.

One CVE
→
Threat intel agent
Impact assessment agent
Patch and remediation agent
→
Orchestrator's final report
AgentFocusTools it is given
Threat intelWhat is it and is it being exploited now?fetch_nvd_data, check_cisa_kev
Impact assessmentHow likely is exploitation and who is affected?fetch_epss_score, fetch_nvd_data
Patch and remediationIs there a fix and how urgent is it?fetch_nvd_data, check_cisa_kev

Each agent only sees the tools relevant to its job. That keeps it focused and stops it reaching for tools that do not belong to its role.

How is this different from L2?

Level 2 also ran parallel specialists and a moderator. A4 goes further:

L2A4
Do agents use tools?No, they reason from the model's trainingYes, each calls live NVD, EPSS and CISA KEV
Agent loopOne call eachEach runs its own tool-calling loop
SynthesisA moderator reads four reportsAn orchestrator reads three reports

Each agent runs the same loop

One generic function runs any specialist. Only the prompt, tools and output schema change:

architectures/a4_multi_agent.py · run_agent_with_tools
async def run_agent_with_tools(
    agent_name: str,
    system_prompt: str,
    user_message: str,
    tools: list[dict],
    output_schema: type,
) -> tuple[Any, list[dict]]:
    """
    Run a single specialist agent through its tool-calling loop.

    Each specialist agent is independent: its own messages list, its own
    tools, its own conversation thread. Agents cannot see each other.

    Returns: (structured_report, tool_call_log)
    """
    messages: list[dict] = [
        {"role": "system", "content": system_prompt},
        {"role": "user",   "content": user_message},
    ]
    tool_log       = []
    max_iterations = 8

    for _ in range(max_iterations):
        response = await client.chat.completions.create(
            model=MODEL,
            messages=messages,
            tools=tools,
            tool_choice="auto",
            temperature=0.1,
            max_tokens=2048,
        )
        _track(response)
        message = response.choices[0].message

        if message.tool_calls:
            messages.append(message.model_dump(exclude_unset=True))

            for tc in message.tool_calls:
                fn_name   = tc.function.name
                args      = json.loads(tc.function.arguments)
                fn        = ALL_TOOL_FUNCTIONS.get(fn_name)
                result    = await fn(**args) if fn else {"error": f"Unknown tool: {fn_name}"}
                result_str = json.dumps(result)

                console.print(f"[dim]    [{agent_name}] → {fn_name}({args})[/dim]")
                tool_log.append({"agent": agent_name, "tool": fn_name, "arguments": args, "result": result})

                messages.append({
                    "role":         "tool",
                    "tool_call_id": tc.id,
                    "content":      result_str,
                })
            continue

        # No more tool calls — produce structured report
        final = await client.chat.completions.create(
            model=MODEL,
            messages=messages + [
                {"role": "user", "content": "Produce your final structured report now."}
            ],
            response_format={
                "type": "json_schema",
                "json_schema": {
                    "name":   output_schema.__name__,
                    "strict": True,
                    "schema": _strict_schema(output_schema),
                },
            },
            temperature=0.1,
            max_tokens=1024,
        )
        _track(final)
        report = output_schema.model_validate(json.loads(final.choices[0].message.content))
        return report, tool_log

    raise RuntimeError(f"Agent {agent_name} exceeded max iterations")

Key points:

  • Independent threads. Each call builds its own messages list. Agents cannot see each other's work.
  • A tool loop with a cap. Up to 8 iterations. If the model stops asking for tools, a final call produces the structured report. Past the cap it raises a RuntimeError.
  • Unknown tools are handled. An unknown tool name becomes an error result instead of a crash, and a test (test_a4_run_agent_with_tools_dispatches_unknown_tool_safely) covers it.

A specialist is just that function with a focused prompt. Here is the threat intel one:

architectures/a4_multi_agent.py · run_threat_intel_agent
async def run_threat_intel_agent(cve_id: str) -> tuple[ThreatIntelReport, list[dict]]:
    return await run_agent_with_tools(
        agent_name="threat_intel",
        system_prompt=(
            "You are a threat intelligence analyst. Your ONLY focus is: "
            "what is this vulnerability, how does it work, and is it being actively exploited right now? "
            "Use fetch_nvd_data for the official description and severity. "
            "Use check_cisa_kev to determine if CISA has confirmed active exploitation. "
            "Do not speculate about impact or remediation — that is handled by other agents."
        ),
        user_message=f"Provide threat intelligence for {cve_id}.",
        tools=THREAT_INTEL_TOOLS,
        output_schema=ThreatIntelReport,
    )

Note the sentence "Do not speculate about impact or remediation, that is handled by other agents." Telling a specialist what not to do is how you keep roles clean.

Fan-out, then fan-in

architectures/a4_multi_agent.py · analyse_cve
async def analyse_cve(
    cve_id: str,
) -> tuple[ThreatIntelReport, ImpactReport, RemediationReport, MultiAgentReport, list[dict]]:
    """
    Full Multi-Agent pipeline:
      1. Dispatch three specialist agents in parallel
      2. Collect their reports
      3. Orchestrator synthesises the final assessment

    The three agents run concurrently — the total time is roughly max(agent_times)
    rather than sum(agent_times).
    """
    _reset_usage()
    console.print(f"\n[dim]  Dispatching three specialist agents for {cve_id}...[/dim]")
    start = time.perf_counter()

    # ── Fan-out: all three agents run concurrently ─────────────────────────────
    (threat, threat_log), (impact, impact_log), (remediation, remediation_log) = (
        await asyncio.gather(
            run_threat_intel_agent(cve_id),
            run_impact_agent(cve_id),
            run_remediation_agent(cve_id),
        )
    )

    console.print("[dim]  All agents complete. Orchestrator synthesising...[/dim]")

    # ── Fan-in: orchestrator synthesises ──────────────────────────────────────
    final = await synthesise_reports(cve_id, threat, impact, remediation)

    elapsed   = time.perf_counter() - start
    all_tools = threat_log + impact_log + remediation_log
    console.print(f"[dim]  Completed in {elapsed:.1f}s ({len(all_tools)} total tool calls across 3 agents)[/dim]")

    return threat, impact, remediation, final, all_tools

The three agents start together with asyncio.gather (the same tool as in L2 and A3), so the wall-clock time is roughly the slowest agent rather than the sum. Then synthesise_reports makes one model call that receives all three reports as JSON and writes the final MultiAgentReport. The orchestrator calls no tools; it only combines what the specialists found.

Note

The file's introduction says the roles are hardcoded and that dynamic subtask assignment is left as an extension. That matches the code: each specialist's task text is fixed (for example, "Provide threat intelligence for CVE-..."), and the orchestrator's real job here is synthesis.

The collaborate function

collaborate returns a Consensus object with a transcript, in three modes: handoff, debate and blackboard. Read it with care, because it is easy to misread.

It first runs the normal analyse_cve. Then it builds the transcript from the finished reports using fixed message templates (the function's docstring now says so). For example, in debate mode the messages are strings like "Round 1: Active exploit=True. Prioritize speed." filled in with values from the reports. No extra model calls happen, and the agents do not actually talk to each other. The transcript shows what a handoff, debate or blackboard exchange would look like in the data model, which is useful for learning the shapes and for building a UI, but it is not real inter-agent negotiation.

It does compute one real signal: disagreement_noted is true when the threat agent says the CVE is actively exploited but the remediation agent rates urgency as medium or low. That mismatch is worth a human's attention. Agent communication is described in specs/E3-agent-communication.md.

You should see three agents dispatched, their tool calls printed as they happen (tagged with the agent's name), a line saying the orchestrator is synthesising, and the final report. It needs an OpenAI key and internet access.

Common mistakes

  • Splitting too early. Several agents cost several times as much. If one prompt can do the job, keep it simple.
  • Overlapping roles. If two agents do similar work you pay twice for the same answer. Draw clear boundaries in the prompts.
  • Assuming independence means diversity. Agents that share one model share its blind spots. Three agents agreeing is not three independent confirmations.
  • No orchestrator rules. The synthesis prompt says urgency must reflect CVSS, EPSS and active exploitation together. Without a rule like that, a synthesiser can drift towards whichever report is most dramatic.
  • Mistaking templates for conversation. See the collaborate section above.

Check yourself

Why give each specialist only a subset of the tools?

It keeps each one focused on its role and avoids it using tools that belong to another agent's job.

Why does the total time roughly equal the slowest agent and not the sum?

The three agents run concurrently with asyncio.gather. Only the orchestrator step waits for all of them.

Do the agents in collaborate really debate?

No. The transcript is built from fixed templates using the finished reports. It illustrates the structure of a debate without any extra model calls.
