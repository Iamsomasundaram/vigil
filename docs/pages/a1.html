Architectures

A1: ReAct

The question this pattern answers: when an agent calls tools, how can I see why it chose each one?

ReAct stands for Reasoning plus Acting. It comes from a 2022 paper (Yao et al.) whose insight was that models do better, and are easier to audit, when they write their reasoning out before they act.

The idea in plain English

Imagine a junior analyst who must narrate aloud: "I'll check NVD first because I need the severity... NVD says 10.0, so next I want to know whether anyone is exploiting it..." You get the answer and the thinking behind it.

Thoughtwhy this step?
→
Actioncall a tool
→
Observationread the result
→
Repeat or answer

Each trip around this loop becomes one record in a trace. The trace is the point of A1.

How is this different from L4?

Level 4 also loops over tools. The difference is where the reasoning lives:

L4 tool useA1 ReAct
You seeWhat was called and what came backWhy it was called, too
ReasoningHidden inside the modelWritten out as text before each call
OutputThe analysisThe analysis plus the reasoning trace

Same tools, same kind of outcome. A1 adds the explanation.

The record of one step

architectures/a1_react.py · ReasoningStep
class ReasoningStep(_Base):
    """
    One cycle of the ReAct loop: Thought → Action → Observation.

    This is the core unit of transparency in ReAct. Every decision the agent
    makes is recorded here with the reasoning that led to it.
    """
    step:        int
    thought:     str  = Field(description="The agent's explicit reasoning before acting")
    action:      str  = Field(description="What the agent decided to do (tool name or 'answer')")
    observation: str  = Field(description="What the agent learned from the action")

And the final report, which carries the facts from all three sources:

architectures/a1_react.py · ReActReport
class ReActReport(_Base):
    """
    Final output of the ReAct investigation.

    Contains both the reasoning trace (HOW the agent reached its conclusions)
    and the final analysis (WHAT it concluded). The trace is what distinguishes
    ReAct from a plain tool-use agent.
    """
    cve_id:             str
    cvss_score:         float       = Field(description="From NVD — current base score")
    cvss_severity:      str         = Field(description="Critical / High / Medium / Low")
    epss_score:         float       = Field(ge=0.0, le=1.0)
    epss_percentile:    float       = Field(ge=0.0, le=1.0)
    in_cisa_kev:        bool        = Field(description="Is this CVE actively exploited? (CISA KEV)")
    patch_available:    bool
    risk_verdict:       str         = Field(description="One-sentence risk summary grounded in all three data sources")
    recommended_action: str
    reasoning_steps:    int         = Field(description="How many Thought→Act→Observe cycles the agent took")
    data_sources:       list[str]   = Field(description="Which tools were actually called")

Notice reasoning_steps and data_sources at the bottom. The report states how many cycles it took and which tools it actually used.

The trick: capturing the Thought

The OpenAI API lets one model reply contain both text and tool calls. The system prompt tells the model to always write a "Thought:" sentence before calling a tool. The code then maps the pieces:

Part of the replyBecomes
message.contentthe Thought
message.tool_callsthe Action
the tool's resultthe Observation

The loop

Read this slowly. It is the whole pattern.

architectures/a1_react.py · run_react_loop
async def run_react_loop(cve_id: str) -> tuple[ReActReport, list[dict]]:
    """
    The ReAct investigation loop.

    Structurally similar to L4's tool loop, but with two critical differences:

    1. The system prompt instructs the model to ALWAYS write a Thought before
       acting. The thought is captured from message.content.

    2. Every Thought → Action → Observation triple is recorded as a
       ReasoningStep, forming the full reasoning trace.

    The trace is the output that makes ReAct valuable. It answers:
      "Why did the agent call those tools in that order?"
      "What was it thinking when it decided to escalate?"
    """
    messages: list[dict] = [
        {
            "role": "system",
            "content": (
                "You are a vulnerability intelligence analyst using the ReAct approach. "
                "BEFORE every tool call or final answer, you MUST write a 'Thought:' sentence "
                "explaining your reasoning — what you know, what you need to find out, and why "
                "you are taking this specific action next. "
                "\n\n"
                "You have three tools: fetch_nvd_data (official CVE data), fetch_epss_score "
                "(exploitation probability), and check_cisa_kev (confirmed active exploitation). "
                "\n\n"
                "Use all three tools before concluding. Your Thought steps are as important as "
                "your final answer — they are the audit trail for your decisions."
            ),
        },
        {
            "role": "user",
            "content": (
                f"Investigate {cve_id}. "
                "Use your tools to gather live data from NVD, EPSS, and CISA KEV, "
                "then provide a grounded risk assessment. "
                "Remember to think out loud before each step."
            ),
        },
    ]

    reasoning_trace: list[dict] = []  # Thought → Action → Observation records
    step_number    = 0
    max_iterations = 12

    while step_number < max_iterations:
        response = await client.chat.completions.create(
            model=MODEL,
            messages=messages,
            tools=TOOLS,
            tool_choice="auto",
            temperature=0.1,
            max_tokens=4096,
        )
        _track(response)
        message = response.choices[0].message

        # ── Extract the Thought from the model's text content ─────────────────
        # When the model follows the system prompt, message.content contains its
        # reasoning. We capture this as the Thought for this step.
        thought = (message.content or "").strip()

        if message.tool_calls:
            # ── Action: the model is calling tools ────────────────────────────
            messages.append(message.model_dump(exclude_unset=True))

            # Execute all tool calls from this turn (may be multiple)
            tool_results = await asyncio.gather(*[
                _execute_tool(tc) for tc in message.tool_calls
            ])

            for tool_call, result_str in zip(message.tool_calls, tool_results):
                step_number += 1
                fn_name  = tool_call.function.name
                args     = json.loads(tool_call.function.arguments)
                result   = json.loads(result_str) if result_str.startswith("{") else {"raw": result_str}

                # Build a human-readable observation summary
                observation = _summarise_observation(fn_name, result)

                console.print(
                    f"[dim]  Step {step_number} │ Thought: {thought[:80]}{'...' if len(thought) > 80 else ''}[/dim]"
                )
                console.print(f"[dim]             │ Action:  {fn_name}({args})[/dim]")
                console.print(f"[dim]             │ Observe: {observation[:80]}[/dim]")

                reasoning_trace.append({
                    "step":        step_number,
                    "thought":     thought,
                    "action":      fn_name,
                    "arguments":   args,
                    "observation": observation,
                    "raw_result":  result,
                })

                messages.append({
                    "role":         "tool",
                    "tool_call_id": tool_call.id,
                    "content":      result_str,
                })

                # Reset thought for subsequent tools in the same turn
                thought = ""

            continue

        # ── No tool calls: model is ready to produce the final report ─────────
        console.print(f"[dim]  Investigation complete ({step_number} steps). Structuring report...[/dim]")

        final_response = await client.chat.completions.create(
            model=MODEL,
            messages=messages + [
                {
                    "role": "user",
                    "content": (
                        "You have completed your investigation. "
                        "Produce the final structured report based only on the data you retrieved. "
                        "Set reasoning_steps to the number of Thought→Act→Observe cycles you completed."
                    ),
                }
            ],
            response_format={
                "type": "json_schema",
                "json_schema": {
                    "name":   "ReActReport",
                    "strict": True,
                    "schema": _strict_schema(ReActReport),
                },
            },
            temperature=0.1,
            max_tokens=2048,
        )
        _track(final_response)

        report = ReActReport.model_validate(
            json.loads(final_response.choices[0].message.content)
        )
        return report, reasoning_trace

    raise RuntimeError(f"ReAct loop exceeded {max_iterations} steps — agent may be stuck")

The beats to find:

  1. The system prompt demands a Thought before every tool call or final answer, and says to use all three tools before concluding.
  2. A model turn with tool calls. The Thought is read from message.content. The tool calls in that turn run together with asyncio.gather.
  3. One trace entry per tool call. Each gets its own step number, the Thought, the action, a short observation and the raw result.
  4. A turn with no tool calls means the model is done. A second call then asks for the final report as structured output, matching ReActReport (the same technique as L1).
  5. A safety cap. The loop stops with a RuntimeError if the agent goes past 12 steps. The counter increases once per tool call, so it caps tool calls, not model turns.

The short human-readable observation printed in the trace is made by a small helper:

architectures/a1_react.py · _summarise_observation
def _summarise_observation(tool_name: str, result: dict) -> str:
    """Produce a short human-readable summary of a tool result for the trace display."""
    if "error" in result:
        return f"ERROR: {result['error']}"
    if tool_name == "fetch_nvd_data":
        return (
            f"CVSS {result.get('cvss_score')} ({result.get('severity')}) — "
            f"{(result.get('description') or '')[:80]}"
        )
    if tool_name == "fetch_epss_score":
        return result.get("note", str(result))
    if tool_name == "check_cisa_kev":
        return result.get("note", str(result))
    return str(result)[:120]

Run it

python architectures/a1_react.py CVE-2021-44228
python architectures/a1_react.py CVE-2014-0160

You need an OpenAI key and an internet connection, because NVD, EPSS and the CISA catalog are live. While it runs you should see lines of the form Step 1 | Thought: ..., then Action: and Observe:, followed by the report. The wording differs on every run.

Warning

The Thought is text the model wrote, not a window into its internals. It is excellent evidence for debugging and audits, but a model can write a tidy rationale that does not fully explain what drove the choice. Treat it as an explanation to check, not as proof.

What to notice in a real trace

  • Does the agent call tools in the same order for different CVEs? If it does, the order is more habit than reasoning.
  • Is the Thought for step 2 actually informed by the observation from step 1?
  • If the model batches several tool calls in one turn, only the first one gets the Thought. The code blanks the Thought for the rest of that turn, so later steps in the same turn show an empty thought.

Try it

Try it

1) Edit the system prompt to say "think in one short sentence" and see how the trace changes. 2) Remove check_cisa_kev from TOOLS and TOOL_FUNCTIONS and see how the verdict changes for a CVE that is in the KEV catalog. 3) Lower max_iterations to 2 and watch the safety cap trigger.

Common mistakes

  • No iteration cap. An agent that keeps asking for tools will loop forever. The cap here is the minimum.
  • Believing the Thought is guaranteed honest. See the warning above.
  • Hiding the trace. The trace is the product. If you do not show or store it, you lose the benefit.
  • Letting a tool error vanish. Tool errors are returned to the model as observations so it can react to them. Keep that.
  • Expecting the same trace twice. Even at low temperature the path can change between runs.

Check yourself

What are the three parts of one ReAct cycle?

Thought (why), Action (the tool call) and Observation (the result). The code records each trio as a step.

Where does the Thought come from in the code?

From the text content of the model's reply (message.content), which the system prompt instructs it to write before every tool call.

What does the safety cap count, and what happens when it is hit?

It counts tool-call steps, up to 12. If exceeded, the loop raises a RuntimeError instead of running forever. A test (test_a1_react_loop_aborts_after_max_iterations) checks this.
