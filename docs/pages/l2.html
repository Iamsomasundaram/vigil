Level 2: Parallel agents

The question this level answers: what if several different experts should look at the same problem, and I do not want to wait for them one at a time?

In L1 each step depended on the one before it, so they had to run in order. Some work has no such dependency. How exploitable a CVE is does not depend on its business impact, so those two analyses can run at the same time.

The idea in plain English

You convene a small committee. Four specialists each read the same file and write their own report independently. A chair then reads all four reports and delivers the verdict.

One CVE
→
Exploitability agent
Impact agent
Patch agent
Business agent
→
Moderator's verdict

This pattern is called fan-out then fan-in. The fan-out is parallel. The final synthesis is sequential, because the moderator needs all four reports first.

What is an "agent" here?

At this level an agent is nothing mysterious. It is three things:

  1. a system prompt that defines a specialist role,
  2. a schema that defines the shape of its report, and
  3. a function that calls the model with both.

Same model, same API, different persona. The four agents are defined as plain data:

levels/l2_parallel.py · AGENTS
AGENTS = [
    {
        "name":    "Exploitability Agent",
        "system":  "You are a penetration tester. Assess how easy this CVE is to exploit. Focus on attack complexity, required privileges, and whether exploit code is publicly available.",
        "schema":  ExploitabilityReport,
    },
    {
        "name":    "Impact Agent",
        "system":  "You are a security architect. Assess the blast radius and data exposure if this CVE is successfully exploited. Focus on CIA triad impacts.",
        "schema":  ImpactReport,
    },
    {
        "name":    "Patch Agent",
        "system":  "You are a patch management specialist. Assess the availability and complexity of fixes for this CVE. Focus on practical remediation guidance.",
        "schema":  PatchReport,
    },
    {
        "name":    "Business Impact Agent",
        "system":  "You are a risk manager. Assess the business and compliance exposure from this CVE. Focus on affected services, regulatory implications, and customer data risk.",
        "schema":  BusinessReport,
    },
]

Each one has its own report class, such as ExploitabilityReport and ImpactReport, so each speaks about its own specialty in typed fields (the same structured-output idea you met in Level 1).

Running one agent

levels/l2_parallel.py · run_agent
async def run_agent(agent: dict, cve_id: str) -> tuple[str, BaseModel]:
    """
    Run a single agent asynchronously.

    Returns (agent_name, result) so we know which output belongs to which agent
    after asyncio.gather() collects everything.

    The `await` keyword is crucial here:
      Without await: the call blocks — other agents must wait
      With await:    Python can context-switch to other agents while waiting
                     for the API response
    """
    schema = agent["schema"]
    response = await client.chat.completions.create(
        model=MODEL,
        messages=[
            {"role": "system", "content": agent["system"]},
            {"role": "user",   "content": f"Analyse this CVE: {cve_id}"},
        ],
        response_format={
            "type": "json_schema",
            "json_schema": {
                "name":   schema.__name__,
                "strict": True,
                "schema": _strict_schema(schema),
            },
        },
        temperature=0.1,
        max_tokens=4096,
    )
    _track(response)
    result = schema.model_validate(json.loads(response.choices[0].message.content))
    return agent["name"], result

The new words are async and await. They let Python start a slow job, such as waiting on the model, and do other work while it waits, instead of freezing. If you have not met them before, read the next section slowly.

Why parallel? A short timing story

If each call takes about three seconds:

ApproachTotal time
One after another (L1 style)about 3 + 3 + 3 + 3 = 12 seconds
All at once (this level)about 3 seconds

The moderator call is added after, because it must wait for all four. You pay for the same number of tokens either way; parallelism saves time, not money. These timings are an illustration, and real latency varies.

async and asyncio.gather, in plain terms

A normal function call blocks: nothing else happens until it returns. An async function can pause at an await and let others run while it waits for the network.

asyncio.gather takes several of these and starts them all together. It returns once every one has finished, with results in the same order you passed them in. Here is the whole pipeline:

levels/l2_parallel.py · analyse_cve
async def analyse_cve(cve_id: str) -> tuple[dict, FinalVerdict]:
    """
    The full fan-out + synthesis pipeline.

    Step 1: Run all four agents IN PARALLEL using asyncio.gather()
    Step 2: Collect their results into a dict
    Step 3: Run the moderator SEQUENTIALLY after all four complete

    asyncio.gather(*coroutines) is the key call:
      - Takes any number of coroutines
      - Starts all of them immediately
      - Waits until ALL of them finish
      - Returns their results in the same order they were passed
    """
    _reset_usage()
    console.print("\n[dim]  Launching 4 agents in parallel...[/dim]")

    # ── Fan-out: all four agents start simultaneously ──────────────────────
    start = time.perf_counter()

    results = await asyncio.gather(
        *[run_agent(agent, cve_id) for agent in AGENTS]
        # ↑ This creates 4 coroutines and runs them all at once.
        # Each yields control while waiting for the API, letting the others run.
    )

    elapsed = time.perf_counter() - start
    console.print(f"[dim]  All 4 agents completed in {elapsed:.1f}s[/dim]")

    # Convert list of (name, result) tuples into a dict
    agent_reports = {name: report for name, report in results}

    # ── Synthesis: moderator runs after all agents complete ────────────────
    console.print("[dim]  Running moderator...[/dim]")
    verdict = await run_moderator(cve_id, agent_reports)

    return agent_reports, verdict

Find these three beats in the code:

  1. Fan-out. asyncio.gather(*[run_agent(agent, cve_id) for agent in AGENTS]) starts all four agents.
  2. Collect. The results become a dictionary keyed by agent name.
  3. Synthesise. run_moderator receives all four reports as its context and returns a FinalVerdict: priority, a patch deadline in days, an executive summary, three actions and a confidence level.

Run it

python levels/l2_parallel.py CVE-2021-44228

You should see a line saying four agents were launched in parallel, then a time for how long they took, then one card per agent and a verdict from the moderator. Compare the reported time with what four separate calls would take.

Note

Agents can disagree. The Patch agent may call the work easy while the Business agent calls the risk severe. That is useful, not a bug: the moderator's job is to weigh them.

Try it

Try it

1) Add a fifth agent, for example a "Compliance Agent", by adding one entry and one report class. Notice how little code a new specialist needs. 2) Time the run, then change asyncio.gather into a plain for loop with await inside and compare the time. 3) Give two agents deliberately conflicting system prompts and read how the moderator handles it.

Common mistakes

  • Parallelising dependent work. If step B needs step A's output, they cannot run together.
  • Calling await one at a time in a loop. That is sequential again. Collect the coroutines and use asyncio.gather.
  • Too many agents at once. Providers limit how many requests you can send per minute. A large fan-out can hit those limits.
  • Assuming more agents means more truth. Four agents share one model and one training set, so they can share the same blind spot.
  • Forgetting the cost. Five calls cost about five times one call.

Check yourself

Why can the four agents run in parallel but the moderator cannot?

The agents are independent of each other. The moderator needs all four reports as input, so it must wait.

Does running in parallel reduce the cost?

No. The same tokens are used. It reduces the waiting time.

In this level, what is an agent?

A system prompt, an output schema and a function that calls the model with them. It does not decide what to do next yet; that comes with routing (L3) and tools (L4).
